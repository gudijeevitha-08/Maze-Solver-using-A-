# Hospital Delivery Robot Planner
**Phase 1:** Maze Solver using A* (Manhattan heuristic), compared with BFS.  
**Phase 2 extension:** Hospital medicine/sample delivery scheduling using a CSP, plus dynamic route planning.

## Requirements
- Python 3.9 or later
- No third-party packages are required.

## Run
```bash
python src/main.py
```

## Run tests
```bash
python -m unittest discover -s tests -v
```

## Problem formulation
- **State:** a grid cell `(row, column)`.
- **Initial state:** `(0, 0)` in the demo maze.
- **Actions:** move one cell up, down, left, or right.
- **Goal test:** current cell equals `(6, 6)`.
- **Step cost:** 1 per move.
- **Heuristic:** Manhattan distance `|r-r_goal| + |c-c_goal|`.

## Algorithms
- **BFS:** queue-based uninformed search; finds a shortest path when every move has equal cost.
- **A\*:** priority is `f(n) = g(n) + h(n)`. Manhattan distance is admissible for four-direction movement with unit costs.
- **CSP scheduler:** tasks are variables, permitted time slots are domains, and shared-robot tasks have inequality constraints. Uses AC-3 domain filtering and MRV variable selection with backtracking.
- **Dynamic routing:** busy/blocked cells are temporarily converted to walls, then A* replans. Rule messages explain why a cell was avoided.

## Example
The program prints the maze, BFS and A* paths, path costs, nodes expanded, a delivery schedule, and a re-planned route around a dynamic obstacle. Exact node counts are generated by running the program; they can vary if the maze or tie-breaking changes.

## Limitations
This is an educational simulation, not a real hospital deployment. Occupancy is represented by manually supplied busy/blocked cells rather than a trained probabilistic sensor model. The sterile-robot/ICU rule is shown as an explanation note and would need actual zone metadata and enforcement in a real system. No patient-identifiable data is used.
